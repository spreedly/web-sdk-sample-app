# ACH Form Integration Guide (Express Checkout)

`SpreedlyACHForm` is a prebuilt bank account form. It runs in one Spreedly-hosted iframe,
like the Express Checkout card form. The customer types the routing and account numbers
into that iframe, the form tokenizes them there, and your page receives the transaction
returned by the Spreedly tokenization API, with the bank numbers already masked.

Use it when you want a ready-made form. If you want to lay out the fields yourself, use
[`SpreedlyACHFields`](../ach-hosted-fields/INTEGRATION_GUIDE.md) (Hosted Fields) instead. To compare
the two, see the [ACH overview](../OVERVIEW.md).

## Overview

1. Load the Express Checkout bundle and create a `SpreedlyACHForm` with your auth details.
2. Call `mount()`. Pass a container to embed the form, or nothing to open it as a dialog.
3. The customer fills in the form and clicks its submit button. The form validates the
   fields and tokenizes inside the iframe.
4. Your page gets `tokenGenerated` with `{ message, tokenResponse, shouldRetain }`, the same
   shape as the Express Checkout card form plus `shouldRetain` (see
   [Saving the account](#saving-the-account)). Your backend runs the purchase.

## Prerequisites

- Spreedly account with an [ACH-capable gateway](https://developer.spreedly.com/docs/ach-payments#ach-gateways) configured
- Spreedly environment key and API credentials
- Auth details generated by your backend (see below)

### Authentication

The constructor needs these five auth details. Generate them on your backend, never in the
browser, because the signature uses your certificate's private key. Follow
[this guide](https://developer.spreedly.com/docs/tokenization#generating-authentication-credentials)
to generate them.

| Property | Type | Description |
|----------|------|-------------|
| `environment_key` | `string` | Your Spreedly environment key |
| `certificate_token` | `string` | Certificate token for iframe security |
| `nonce` | `string` | One-time random string |
| `timestamp` | `string` | UTC timestamp |
| `signature` | `string` | SHA-256 signature of `nonce + timestamp + certificate_token`, signed with your certificate's private key |

## Step 1: Load the SDK

`SpreedlyACHForm` ships in the Express Checkout bundle and is exposed as
`window.SpreedlyACHForm`.

```html
<script src="https://core.spreedly.com/checkout/elements/{version}/express-checkout.js"></script>
```

## Step 2: Create the instance and listen

```javascript
const form = new SpreedlyACHForm({
  environment_key: authParams.environment_key,
  certificate_token: authParams.certificate_token,
  nonce: authParams.nonce,
  signature: authParams.signature,
  timestamp: authParams.timestamp,
});

form.on('tokenGenerated', ({ tokenResponse }) => {
  const token = tokenResponse.payment_method.token;
  // Send the token to your backend and run the purchase (Step 5).
});

form.on('error', error => {
  // See "Handling errors" for what `error` can be.
  console.error(error);
});
```

The constructor throws if any auth field is missing.

## Step 3: Mount the form

### Embedded

Give the container a height. The form fills it and doesn't size itself, the same as the
Express Checkout card form. The form is about 500 px tall, or about 555 px with the
save-account checkbox, so use at least 600 px or the form scrolls inside its box. A container
with no height, or only a `min-height`, leaves the iframe at the browser's default height of
150 px, so only the title and the first field show.

```html
<div id="ach-form" style="height: 600px"></div>
```

```javascript
form.mount({ parentContainerId: 'ach-form' });
```

### Dialog

Leave out `parentContainerId`. The form opens as a dialog: a centered card (up to 560 px wide,
sized to its content) over a dimmed page, with its own close button. You don't set a height.
Clicking outside the card doesn't close it.
When the customer closes it, you get `close`.

```javascript
form.on('close', () => {
  // The customer closed the dialog.
});

form.mount();
```

### Customizing

Every option is optional.

```javascript
form.mount({
  parentContainerId: 'ach-form',
  uiConfig: {
    textConfig: { title: 'Pay by bank', submitBtnText: 'Pay' },
    achFormFields: {
      bank_account_holder_type: { isHidden: true },
      bank_routing_number: { label: 'ABA routing number' },
    },
    showSaveAccountCheckbox: true,
  },
  submitParams: { metadata: { order_id: '1234' } },
});
```

See [Styling](#styling) to change colors and fonts.

`parentContainerId` is the same option name as the card form's `expressCheckout()`.

If your gateway needs contact or billing details, show the optional fields: `email`,
`phone_number`, `address1`, `address2`, `city`, `state`, `zip` and `country`. They are
hidden by default; the customer fills them in.

```javascript
uiConfig: {
  achFormFields: {
    email: { isHidden: false, isRequired: true },
    zip: { isHidden: false },
  },
}
```

The account holder name, routing number and account number fields are always shown and
always required. You can change their label, placeholder, size and styles. `placeholder` has
no effect on the two dropdowns (account type, account holder type). See the
[API reference](./API_REFERENCE.md) for every option and default.

### Styling

`styles` is a plain object of CSS values, grouped by part of the form. Every key is optional.

```javascript
form.mount({
  uiConfig: {
    styles: {
      typography: { fontFamily: 'Inter, sans-serif' },
      button: {
        backgroundColor: '#1a73e8',
        color: '#ffffff',
        hover: { backgroundColor: '#1557b0' },
      },
      textfield: {
        borderColor: '#cccccc',
        active: { borderColor: '#1a73e8' },
      },
      paper: { backgroundColor: '#ffffff' },
    },
  },
});
```

| Key            | What it styles | Keys it takes |
| -------------- | -------------- | ------------- |
| `button`       | The submit button | `backgroundColor`, `borderColor`, `color`, `fontSize`, `fontWeight`, `textTransform`, `hover: { backgroundColor, borderColor, color }` |
| `textfield`    | All input fields | `backgroundColor`, `color`, `borderColor`, `fontSize`, `fontWeight`, `placeholder: { color }`, `active: { borderColor }`, `hover: { borderColor }` |
| `checkbox`     | The "save this account" checkbox | `borderColor` (unticked), `backgroundColor` (ticked), `hover: { backgroundColor, color }` |
| `typography`   | Text | `fontFamily` |
| `loader`       | The spinner shown while the form loads | `color` |
| `paper`        | The form background | `backgroundColor` |
| `rootFontSize` | Base font size per screen width | `xs`, `sm`, `md`, `lg`, `xl` |

To style one field, set `styles` on that field in `achFormFields`. It takes the same keys as
`textfield`:

```javascript
uiConfig: {
  achFormFields: {
    bank_account_number: { styles: { backgroundColor: '#f5f5f5' } },
  },
}
```

## Step 4: Handle the token

`tokenGenerated` gives you the payment method and `shouldRetain`. The bank numbers in the
payment method are already masked, so you can safely show the last digits to the customer,
for example "Checking account ending in 3210":

```javascript
form.on('tokenGenerated', ({ tokenResponse, shouldRetain }) => {
  const pm = tokenResponse.payment_method;
  console.log('Token:', pm.token);
  console.log('Account ending in:', pm.account_number_display_digits); // e.g. '3210'
  console.log('Account type:', pm.account_type);                       // 'checking' | 'savings'
  console.log('Save for later:', shouldRetain);                        // see "Saving the account"

  // Send pm.token (and shouldRetain) to your backend to run the purchase.
});
```

The form clears itself after a successful tokenization, but it doesn't close itself. Call
`form.close()` when you're done with it, for example after showing a confirmation.

## Step 5: Run the purchase from your backend

After `tokenGenerated` fires, send the token to your backend and run a purchase against an
ACH-capable gateway:

```http
POST https://core.spreedly.com/v1/gateways/{ach_gateway_token}/purchase.json
Authorization: Basic base64(environment_key:access_secret)
Content-Type: application/json

{
  "transaction": {
    "payment_method_token": "...",
    "amount": 1000,
    "currency_code": "USD"
  }
}
```

> **Important:** Run the purchase from your backend, not the browser. Your access secret
> must never be exposed client-side.

## Saving the account

With `uiConfig.showSaveAccountCheckbox: true`, the form shows a "Save this account for
future payments" checkbox. It's hidden by default. `tokenGenerated` always has
`shouldRetain`: `true` if the customer ticked the checkbox, `false` if they didn't or it
wasn't shown.

The token you get is for a cached payment method, and the checkbox doesn't retain it — the
same as the Express Checkout card form. Spreedly removes cached payment methods after a short
time, so if `shouldRetain` is `true`, retain it from your backend. There are two ways:

- Add `"retain_on_success": true` to the purchase request. The payment method is kept only if
  the purchase succeeds.
- Or call the retain API on its own:

```http
PUT https://core.spreedly.com/v1/payment_methods/{payment_method_token}/retain.json
Authorization: Basic base64(environment_key:access_secret)
```

## Handling errors

The form shows its own field errors, like a missing name or an invalid routing number, next
to the field. Those don't fire `error`.

Everything else fires `error`, and the form shows nothing for it, so show the message on your
page. The form keeps what the customer typed, so they can fix it and submit again. If the
error is about the auth details, see [Refreshing the auth details](#refreshing-the-auth-details).

```javascript
form.on('error', (error) => {
  if (typeof error === 'string') {
    // An SDK message, for example 'Please wait before submitting again'.
    showMessage(error);
  } else if (Array.isArray(error?.errors)) {
    // The Spreedly tokenization API rejected the request.
    showMessage(error.errors.map(e => e.message).join(' '));
  } else {
    showMessage('Something went wrong. Please try again.');
  }
});
```

| Cause | `error` payload |
| ----- | --------------- |
| Submit within 2 seconds of the last one | `'Please wait before submitting again'` |
| The Spreedly tokenization API rejects the request | The API's error response body |
| The Spreedly tokenization API responds without a token | `'No payment method token received from ACH API'` |
| The request fails without a response (network) | The network error message, or `'ACH tokenization failed'` |

For the keys in the API's error response body, see the [Error Keys Reference](../../errors/ERROR_KEYS_REFERENCE.md).

### Refreshing the auth details

Each set of auth details works for one request to Spreedly, and expires 30 minutes after it's
generated. When `error` has the key `errors.replayed_tokenization_nonce` or
`errors.invalid_tokenization_timestamp`, get new auth details from your backend, pass them to
`updateAuthDetails`, and ask the customer to submit again:

```javascript
const NEW_AUTH_KEYS = ['errors.replayed_tokenization_nonce', 'errors.invalid_tokenization_timestamp'];

form.on('error', async (error) => {
  if (error?.errors?.some(e => NEW_AUTH_KEYS.includes(e.key))) {
    form.updateAuthDetails(await fetchAuthDetailsFromYourBackend());
    showMessage('Please try again.');
    return;
  }
  showMessage(error);
});
```

## Canadian bank accounts

The routing number field takes the 9-digit electronic format: `0`, then the 3-digit
institution number, then the 5-digit transit number. For example, institution `001` and
transit `12345` is `000112345`. Canadian cheques print the transit and institution numbers
separately, so consider telling Canadian customers this format in your page copy or in the
field placeholder (`achFormFields.bank_routing_number.placeholder`).

## Closing and cleanup

- `close()` removes the form. Your `on()` callbacks stay, so you can call `mount()` again.
- `destroy()` removes the form and tears the instance down. Create a new `SpreedlyACHForm`
  to show the form again.

## Complete example

A full page you can start from. It opens the form as a dialog when the customer clicks a
button. Replace the auth details with ones from your backend.

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Pay by bank account</title>
  <style>
    button { padding: 12px 24px; background: #0a0a0a; color: #fff; border: none; border-radius: 6px; cursor: pointer; }
    #result { margin-top: 20px; }
  </style>
</head>
<body>
  <h1>Checkout</h1>
  <button id="pay-by-bank">Pay by bank account</button>
  <div id="result"></div>

  <script src="https://core.spreedly.com/checkout/elements/{version}/express-checkout.js"></script>
  <script>
    const result = document.getElementById('result');

    // 1. Initialize
    const form = new SpreedlyACHForm({
      environment_key: 'your_environment_key',
      certificate_token: 'your_certificate_token',
      nonce: 'generated_nonce',
      signature: 'generated_signature',
      timestamp: 'generated_timestamp',
    });

    // 2. Event handlers
    form.on('tokenGenerated', async ({ tokenResponse, shouldRetain }) => {
      const pm = tokenResponse.payment_method;
      form.close();
      result.textContent = `Paying with the account ending in ${pm.account_number_display_digits}...`;

      // Your backend runs the purchase, and retains the account if shouldRetain is true.
      await fetch('/your-backend/ach-purchase', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ token: pm.token, retain: shouldRetain }),
      });
      result.textContent = 'Payment submitted.';
    });

    form.on('error', (error) => {
      if (typeof error === 'string') {
        result.textContent = error;
      } else if (Array.isArray(error?.errors)) {
        result.textContent = error.errors.map(e => e.message).join(' ');
      } else {
        result.textContent = 'Something went wrong. Please try again.';
      }
    });

    form.on('close', () => {
      // The customer closed the dialog without paying.
    });

    // 3. Open the form
    document.getElementById('pay-by-bank').addEventListener('click', () => {
      result.textContent = '';
      form.mount({
        uiConfig: {
          textConfig: { title: 'Pay by bank', submitBtnText: 'Pay' },
          showSaveAccountCheckbox: true,
        },
        submitParams: { metadata: { order_id: '1234' } },
      });
    });
  </script>
</body>
</html>
```

## Testing

Use these test bank details with Spreedly's test gateway:

| Field | Value |
| ----- | ----- |
| Routing number | `021000021` |
| Account number | `9876543210` |

The test gateway approves a purchase only with this account number. Any other valid account
number still tokenizes, but the purchase fails, which is useful for testing your failure path.
See [Spreedly's test data](https://developer.spreedly.com/docs/test-data) for more.

To test against Spreedly's staging environment, load the SDK from `core-test.spreedly.com`:

```html
<script src="https://core-test.spreedly.com/checkout/elements/{version}/express-checkout.js"></script>
```

## Troubleshooting

### Only the title and one field show

The embedded form's container has no height, or only a `min-height`. Give it a fixed height of
at least 600 px (see [Embedded](#embedded)).

### The form doesn't appear

- For embedded mode, make sure the container is in the page before you call `mount()`. If it
  isn't, the SDK logs a warning and mounts nothing.
- `mount()` does nothing if the form is already mounted. Call `close()` first.

### CSP errors

If your page has a Content Security Policy, allow Spreedly's domains for scripts and frames:

```html
<meta http-equiv="Content-Security-Policy" content="
  frame-src https://core.spreedly.com https://core-test.spreedly.com;
  script-src https://core.spreedly.com https://core-test.spreedly.com;
">
```

### No token comes back

1. Check that the auth details are fresh. Generate a new nonce, timestamp and signature for
   each page load.
2. Look at the payload of your `error` callback. It tells you what failed (see
   [Handling errors](#handling-errors)).

## Security notes

- The routing and account numbers are typed into the Spreedly-hosted iframe and tokenized
  from inside it. They are never in your page's DOM or in messages to your page.
- The account number field is masked by default, with a show/hide toggle.
- The form clears the numbers after a successful tokenization. After a failure it keeps
  them, so the customer can correct a mistake without retyping.
- `tokenGenerated` carries the transaction returned by the Spreedly tokenization API, where
  the bank numbers are already masked (`routing_number: "021*"`, `account_number: "*3210"`,
  plus the `…_display_digits` fields). You never get the full numbers.
- The iframe only accepts messages from the page that first talks to it, and accepts the
  auth params only once.
