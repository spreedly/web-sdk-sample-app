# ACH Hosted Fields Integration Guide

`SpreedlyACHFields` collects a US or Canadian bank account in two Spreedly-hosted secure
fields: routing number and account number. The numbers are entered in Spreedly-hosted iframes
and tokenized from inside them, so they never enter your application state — the same
secure-field model as the card number and CVV hosted fields. You lay out the rest of the form
(name, account type) yourself.

For a ready-made form instead, see the [ACH Form Integration Guide](../ach-form/INTEGRATION_GUIDE.md).
To compare the two, see the [ACH overview](../OVERVIEW.md).

## Overview

1. Create a `SpreedlyACHFields` instance and mount the two secure fields (routing +
   account) into container elements you provide.
2. The customer types the numbers into the Spreedly-hosted iframes. Non-sensitive
   fields (name, account type, holder type, bank name) stay as your own inputs.
3. Call `submit(formData)` with only those non-sensitive fields — the SDK tokenizes
   inside the account iframe and emits `tokenGenerated` with `{ message, tokenResponse }` —
   the whole transaction returned by the Spreedly tokenization API, the same shape as card
   hosted fields.
4. Your backend runs a purchase against an ACH-capable gateway using the token.

## Prerequisites

- Spreedly account with an [ACH-capable gateway](https://developer.spreedly.com/docs/ach-payments#ach-gateways) configured
- Spreedly environment key and API credentials
- Auth details generated by your backend (see below)
- **Secure tokenization enabled** for your environment — see [Enable secure tokenization](../../tokenization/hosted-fields/INTEGRATION_GUIDE.md#enable-secure-tokenization-required)

### Authentication

The constructor needs these five auth details. Generate them on your backend, never in the
browser, because the signature uses your certificate's private key. Follow
[this guide](https://developer.spreedly.com/docs/tokenization#generating-authentication-credentials)
to generate them.

| Property | Type | Description |
|----------|------|-------------|
| `environment_key` | `string` | Your Spreedly environment key |
| `certificate_token` | `string` | Certificate token for iframe security |
| `nonce` | `string` | One-time random string |
| `timestamp` | `string` | UTC timestamp |
| `signature` | `string` | SHA-256 signature of `nonce + timestamp + certificate_token`, signed with your certificate's private key |

## Step 1: Load the SDK

`SpreedlyACHFields` ships in the Hosted Fields bundle and is exposed as `window.SpreedlyACHFields`.

```html
<script src="https://core.spreedly.com/checkout/sdk/{version}/index.js"></script>
```

> `SpreedlyACHFields` is in the Hosted Fields bundle only. On an Express Checkout page,
> use the prebuilt [`SpreedlyACHForm`](../ach-form/INTEGRATION_GUIDE.md) instead.

## Step 2: Add containers for the two fields

Provide two empty `<div>` containers in your HTML. The SDK will inject iframes into them.

```html
<p>Routing number</p>
<div id="ach-routing"></div>

<p>Account number</p>
<div id="ach-account"></div>
```

Size and style these containers with your own CSS; the SDK renders a borderless
iframe that fills each one. A `<label for>` can't point into an iframe, so use plain text
for the visible label. Each input has its own accessible name ("Bank routing number",
"Bank account number"); change it with `setLabel`.

## Step 3: Initialize the SDK

```javascript
const ach = new SpreedlyACHFields({
  environment_key: 'your_environment_key',
  certificate_token: 'your_certificate_token',
  nonce: 'generated_nonce',
  timestamp: 'generated_timestamp',
  signature: 'generated_signature',
});
```

## Step 4: Register event handlers, and then mount the secure fields

```javascript
ach.on('ready', () => {
  // Both fields are mounted and connected — safe to customize them now.
  ach.setPlaceholder('routing', 'Routing number');
  ach.setPlaceholder('account', 'Account number');
});

ach.on('tokenGenerated', ({ tokenResponse }) => {
  const token = tokenResponse.payment_method.token;
  // POST `token` to your backend to run the gateway purchase.
});

ach.on('error', (error) => {
  console.error('ACH error:', error);
});

ach.inAppElements({
  routing: { containerId: 'ach-routing' }, // ids of your container elements
  account: { containerId: 'ach-account' },
});
```

Wait for `ready` before calling any other method — it fires once both iframes are
loaded and connected to each other. The account field is masked by default; call
`toggleMask()` to reveal it (see [Show/hide button](#a-showhide-button-for-the-account-number)).

## Step 5: Collect the non-sensitive fields and submit

The customer types the routing and account numbers into the secure fields. Everything
else (name, account type, holder type, bank name) is collected in your own inputs and
passed to `submit`, with the field names of the Spreedly API — the same convention as the card
`submit()`. `metadata` and `mandate` go in the second argument:

```javascript
ach.submit(
  {
    full_name: 'Bob Smith',              // OR first_name + last_name
    bank_account_type: 'checking',       // 'checking' | 'savings'
    bank_account_holder_type: 'personal', // 'personal' | 'business'
    bank_name: 'First Bank of Elbonia',  // optional
  },
  { metadata: { order_id: '1234' } }     // optional
);
```

If your gateway needs contact or billing details, add `email`, `phone_number`, `address1`,
`address2`, `city`, `state`, `zip` and `country` to the first argument. Other keys are
ignored.

The SDK checks the numbers inside the iframe:
- **Routing number:** a valid US routing number, or a Canadian one (9 digits starting with
  `0`).
- **Account number:** 4–17 digits.

On success it emits `tokenGenerated` and securely clears the fields. If a check fails, or the
request fails, it emits `error` instead (see [Handling errors](#handling-errors)). A submit
that passes these checks starts a 2-second window in which further submits are rejected, and a
submit while a request is still running is ignored.

> Any `bank_routing_number` / `bank_account_number` keys you pass to `submit` are ignored —
> those values come only from the secure fields.

### Account holder name

Send the name one of two ways. One of them is required: without a name, the Spreedly
tokenization API rejects the request (`422 "Full name can't be blank"`).

- `full_name` — one field: `ach.submit({ full_name: 'Bob Smith', … })`
- `first_name` + `last_name` — two fields: `ach.submit({ first_name: 'Bob', last_name: 'Smith', … })`

Use whichever matches your form. If you send both, both are sent. The SDK doesn't check the
name before submitting, so check it in your own form; otherwise the API's error arrives on
`error`.

## Step 6: Handle the token

`tokenGenerated` gives you the payment method. The bank numbers in it are already masked, so
you can safely show the last digits to the customer, for example "Checking account ending in
3210":

```javascript
ach.on('tokenGenerated', ({ tokenResponse }) => {
  const pm = tokenResponse.payment_method;
  console.log('Token:', pm.token);
  console.log('Account ending in:', pm.account_number_display_digits); // e.g. '3210'
  console.log('Account type:', pm.account_type);                       // 'checking' | 'savings'
  console.log('Bank:', pm.bank_name);                                  // if you sent one

  // Send pm.token to your backend to run the purchase.
});
```

## Step 7: Run the purchase from your backend

After `tokenGenerated` fires, send the token to your backend and run a purchase against
an ACH-capable gateway:

```http
POST https://core.spreedly.com/v1/gateways/{ach_gateway_token}/purchase.json
Authorization: Basic base64(environment_key:access_secret)
Content-Type: application/json

{
  "transaction": {
    "payment_method_token": "...",
    "amount": 1000,
    "currency_code": "USD"
  }
}
```

> **Important:** Run the purchase from your backend, not the browser. Your access
> secret must never be exposed client-side.

## Saving the account

The token you get is for a cached payment method. Spreedly removes cached payment methods
after a short time, so if the customer wants to pay with this account again later, retain it
from your backend. There are two ways:

- Add `"retain_on_success": true` to the purchase request. The payment method is kept only if
  the purchase succeeds.
- Or call the retain API on its own:

```http
PUT https://core.spreedly.com/v1/payment_methods/{payment_method_token}/retain.json
Authorization: Basic base64(environment_key:access_secret)
```

If you offer a "Save this account" checkbox, read it in your submit handler and pass its value
to your backend along with the token.

## Handling errors

`error` gets a string when the SDK stops the submit itself, and the API's error response body
when the Spreedly tokenization API rejects the request. Handle both:

```javascript
ach.on('error', (error) => {
  if (typeof error === 'string') {
    // An SDK check failed, for example 'Routing number is invalid'.
    showMessage(error);
  } else if (Array.isArray(error?.errors)) {
    // The Spreedly tokenization API rejected the request.
    showMessage(error.errors.map(e => e.message).join(' '));
  } else {
    showMessage('Something went wrong. Please try again.');
  }
});
```

| Cause | `error` payload |
| ----- | --------------- |
| Invalid routing or account number | `'Routing number is invalid'` or `'Account number is invalid'`. `validation` fires first with the field state. |
| Submit within 2 seconds of the last one | `'Please wait before submitting again'` |
| Different auth details than the first submit | `'Auth credentials cannot be changed after initial use'` |
| The Spreedly tokenization API rejects the request | The API's error response body (for example, for a missing name) |
| The Spreedly tokenization API responds without a token | `'No payment method token received from ACH API'` |
| The request fails without a response (network) | The network error message, or `'ACH tokenization failed'` |

For the keys in the API's error response body, see the [Error Keys Reference](../../errors/ERROR_KEYS_REFERENCE.md).

### Refreshing the auth details

Each set of auth details works for one request to Spreedly, and expires 30 minutes after it's
generated. When `error` has the key `errors.replayed_tokenization_nonce` or
`errors.invalid_tokenization_timestamp`, get new auth details from your backend, pass them to
`updateAuthDetails`, and submit again. Retry once; if it fails again, check how your backend
generates the auth details.

```javascript
const NEW_AUTH_KEYS = ['errors.replayed_tokenization_nonce', 'errors.invalid_tokenization_timestamp'];
let retried = false;

ach.on('error', async (error) => {
  const needsNewAuth = error?.errors?.some(e => NEW_AUTH_KEYS.includes(e.key));
  if (needsNewAuth && !retried) {
    retried = true;
    ach.updateAuthDetails(await fetchAuthDetailsFromYourBackend());
    ach.submit(formData); // the same form data as before
    return;
  }
  showMessage(error);
});
```

## Your submit button

### Enabling it only when both numbers are valid

`fieldStateChange` reports the state of both fields as the customer types — lengths and
validity only, never the values. Use it to enable your submit button:

```javascript
ach.on('fieldStateChange', ({ validRouting, validAccount }) => {
  submitButton.disabled = !(validRouting && validAccount);
});
```

`validate()` posts a one-off snapshot on the `validation` event with the same shape.

### Disabling it while the request runs

Disable the button when the customer submits, and turn it back on when the result comes in.
This stops double clicks and the "Please wait before submitting again" error:

```javascript
form.addEventListener('submit', (event) => {
  event.preventDefault();
  submitButton.disabled = true;
  ach.submit({ full_name: nameInput.value });
});

ach.on('tokenGenerated', () => { submitButton.disabled = false; });
ach.on('error', () => { submitButton.disabled = false; });
```

`error` also fires when the SDK blocks the submit (for example, an invalid routing number), so
the button always comes back.

## Styling the fields

Call these after `ready`:

- `setStyles(field, styles)` styles the input text: font, size, color, padding.
- `setPlaceholderStyles(styles)` styles the placeholder text of both fields.
- `setPlaceholder(field, text)` and `setLabel(field, label)` set the placeholder and the
  accessible name.

Web fonts your page loads don't load inside the iframes. Pass a `fontFamily` the browser
already has, or the iframe uses the browser's default font. If you put your own Show button
over the account field, leave room for it with `paddingRight`.

```javascript
ach.on('ready', () => {
  const styles = { fontFamily: 'Helvetica, Arial, sans-serif', fontSize: '16px', color: '#111' };
  ach.setStyles('routing', styles);
  ach.setStyles('account', { ...styles, paddingRight: '64px' });
  ach.setPlaceholderStyles({ color: '#9aa0a6' });
});
```

Both fields already use a numeric keypad on phones, so you don't need to set an input type.

### Highlighting the field in focus

The fields sit inside your containers, so you can style the container when the customer
clicks into a field. `fieldStateChange` tells you which field gained or lost focus:

```javascript
ach.on('fieldStateChange', ({ field, action }) => {
  const container = document.getElementById(field === 'routing' ? 'ach-routing' : 'ach-account');
  if (action === 'focus') container.classList.add('focused');
  if (action === 'blur') container.classList.remove('focused');
});
```

```css
#ach-routing.focused,
#ach-account.focused {
  border-color: #1a73e8;
}
```

### A show/hide button for the account number

The account number is masked by default. `toggleMask()` switches it between masked and
visible. Put your own button next to the field (or over it, with `paddingRight` as above):

```javascript
let accountShown = false;

toggleButton.addEventListener('click', () => {
  ach.toggleMask();
  accountShown = !accountShown;
  toggleButton.textContent = accountShown ? 'Hide' : 'Show';
});
```

`reload()` masks the field again, so set `accountShown` back to `false` in your `ready`
callback if you use `reload()`.

### Showing an error on a field

The fields don't show errors themselves. To mark an invalid field, for example with a red
border, call `setStyles` in your `validation` callback. `setStyles` changes only the
properties you pass, so set the border back when the number is valid:

```javascript
ach.on('validation', ({ validRouting, validAccount }) => {
  ach.setStyles('routing', { border: validRouting ? '1px solid #ccc' : '1px solid red' });
  ach.setStyles('account', { border: validAccount ? '1px solid #ccc' : '1px solid red' });
});
```

If the border is on your container instead, add or remove a CSS class on the container, as in
the [complete example](#complete-example).

`validation` fires when you call `validate()` and when `submit()` is blocked by an invalid
number. To update the border as the customer types, do the same in a `fieldStateChange`
callback.

## Starting over and cleanup

- `resetFields()` clears both fields and securely wipes the held values.
- `reload()` replaces both iframes with new ones in the same containers. Your callbacks stay
  and `ready` fires again; apply your `set*` customizations again in `ready`.
- `destroy()` removes the fields and tears the instance down. Create a new
  `SpreedlyACHFields` to show the fields again.
- `removeHandlers()` removes every `on()` callback. The fields keep working.
- `isLoaded()` tells you whether the fields are mounted.

## Canadian bank accounts

The routing number field takes the 9-digit electronic format: `0`, then the 3-digit
institution number, then the 5-digit transit number. For example, institution `001` and
transit `12345` is `000112345`. Canadian cheques print the transit and institution numbers
separately, so consider telling Canadian customers this format in your page copy or in the
field placeholder (`setPlaceholder('routing', …)`).

## Complete example

A full page you can start from. Replace the auth details with ones from your backend.

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Pay by bank account</title>
  <style>
    .form-group { margin-bottom: 15px; }

    input, select { height: 40px; width: 100%; padding: 0 10px; border: 1px solid #ccc; border-radius: 4px; box-sizing: border-box; }
    .hosted-field { height: 40px; border: 1px solid #ccc; border-radius: 4px; }
    .hosted-field.focused { border-color: #1a73e8; }
    .hosted-field.invalid { border-color: #d93025; }
    .account-row { display: flex; gap: 8px; }

    button:disabled { opacity: 0.5; cursor: not-allowed; }
    #toggle-mask { padding: 0 12px; background: #eee; color: #111; }
    #result { margin-top: 20px; }
  </style>
</head>
<body>
  <h1>Pay by bank account</h1>

  <form id="ach-form">
    <div class="form-group">
      <label for="full-name">Account holder name</label>
      <input id="full-name" autocomplete="name" required>
    </div>

    <div class="form-group">
      <label for="account-type">Account type</label>
      <select id="account-type">
        <option value="checking">Checking</option>
        <option value="savings">Savings</option>
      </select>
    </div>

    <div class="form-group">
      <p>Routing number</p>
      <div id="ach-routing" class="hosted-field"></div>
    </div>

    <div class="form-group">
      <p>Account number</p>
      <div class="account-row">
        <div id="ach-account" class="hosted-field"></div>
        <button type="button" id="toggle-mask">Show</button>
      </div>
    </div>

    <button type="submit" id="submit-btn" disabled>Pay</button>
  </form>

  <div id="result"></div>

  <script src="https://core.spreedly.com/checkout/sdk/{version}/index.js"></script>
  <script>
    const submitButton = document.getElementById('submit-btn');
    const toggleButton = document.getElementById('toggle-mask');
    const result = document.getElementById('result');
    const containers = {
      routing: document.getElementById('ach-routing'),
      account: document.getElementById('ach-account'),
    };

    // 1. Initialize
    const ach = new SpreedlyACHFields({
      environment_key: 'your_environment_key',
      certificate_token: 'your_certificate_token',
      nonce: 'generated_nonce',
      timestamp: 'generated_timestamp',
      signature: 'generated_signature',
    });

    // 2. Event handlers
    ach.on('ready', () => {
      const styles = { fontFamily: 'Helvetica, Arial, sans-serif', fontSize: '16px', color: '#111' };
      ach.setStyles('routing', styles);
      ach.setStyles('account', styles);
      ach.setPlaceholder('routing', '9 digits');
      ach.setPlaceholder('account', 'Account number');
      submitButton.disabled = false;
    });

    ach.on('fieldStateChange', ({ field, action }) => {
      if (action === 'focus') containers[field].classList.add('focused');
      if (action === 'blur') containers[field].classList.remove('focused');
    });

    ach.on('validation', ({ validRouting, validAccount }) => {
      containers.routing.classList.toggle('invalid', !validRouting);
      containers.account.classList.toggle('invalid', !validAccount);
    });

    ach.on('tokenGenerated', ({ tokenResponse }) => {
      const pm = tokenResponse.payment_method;
      result.textContent = `Bank account ending in ${pm.account_number_display_digits} saved.`;
      submitButton.disabled = false;
      // Send pm.token to your backend to run the purchase.
    });

    ach.on('error', (error) => {
      if (typeof error === 'string') {
        result.textContent = error;
      } else if (Array.isArray(error?.errors)) {
        result.textContent = error.errors.map(e => e.message).join(' ');
      } else {
        result.textContent = 'Something went wrong. Please try again.';
      }
      submitButton.disabled = false;
    });

    // 3. Mount the secure fields
    ach.inAppElements({
      routing: { containerId: 'ach-routing' },
      account: { containerId: 'ach-account' },
    });

    // 4. Show/hide the account number
    let accountShown = false;
    toggleButton.addEventListener('click', () => {
      ach.toggleMask();
      accountShown = !accountShown;
      toggleButton.textContent = accountShown ? 'Hide' : 'Show';
    });

    // 5. Submit
    document.getElementById('ach-form').addEventListener('submit', (event) => {
      event.preventDefault();
      submitButton.disabled = true;
      result.textContent = '';

      ach.submit(
        {
          full_name: document.getElementById('full-name').value,
          bank_account_type: document.getElementById('account-type').value,
          bank_account_holder_type: 'personal',
        },
        { metadata: { order_id: '1234' } }
      );
    });
  </script>
</body>
</html>
```

## Troubleshooting

### The fields don't appear

- Make sure both container `<div>`s are in the page before you call `inAppElements()`. If one
  is missing, nothing is mounted and the browser console shows a warning naming it.
- Give the containers a height. The iframes fill their container.
- Wait for `ready` before enabling your form.

### CSP errors

If your page has a Content Security Policy, allow Spreedly's domains for scripts and frames:

```html
<meta http-equiv="Content-Security-Policy" content="
  frame-src https://core.spreedly.com https://core-test.spreedly.com;
  script-src https://core.spreedly.com https://core-test.spreedly.com;
">
```

### No token comes back

1. Check that the auth details are fresh. Generate a new nonce, timestamp and signature for
   each page load.
2. Check that you send a name: `full_name`, or `first_name` and `last_name`.
3. Look at the payload of your `error` callback. It tells you what failed (see
   [Handling errors](#handling-errors)).

## Security notes

- The routing and account numbers are entered in Spreedly-hosted iframes and tokenized
  from inside them. They are never in your page's DOM, your `submit` payload or messages to
  your page.
- The account field is masked by default. `fieldStateChange` / `validation` carry only
  lengths and validity.
- The SDK securely clears the held values after a successful tokenization and on
  `resetFields()`. `reload()` and `destroy()` remove the iframes, and the values are
  discarded with them.
- `tokenGenerated` carries the transaction returned by the Spreedly tokenization API, where
  the bank numbers are already masked (`routing_number: "021*"`, `account_number: "*3210"`,
  plus the `…_display_digits` fields). You never get the full numbers.
- The iframes only accept messages from the page that first talks to them, and the auth
  details can't be changed after the first submit.
