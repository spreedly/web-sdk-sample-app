Apple Pay (local SDK)

Pay with Apple Pay through SpreedlyApplePay. Test data only: run the sheet with an Apple sandbox tester account.

Update total calls setTotal(): the next tap opens with the new amount, without redrawing the button.

Event log

Debug switches

They only change this page's callbacks, in this browser.

M13: open this page with &skipAppleScript=1 to leave out Apple's script.

SDK Configuration

Apple Pay config options. Changing one redraws the button. The page always sets merchantIdentifier, onValidateMerchant and getAuthDetails.

Charging
When to charge processPayment

Without processPayment the sheet shows success as soon as the token exists, and the page charges after. With it, the page charges while the sheet is open, and the sheet shows the real result.

Wallet order tracking orderDetails

Returned from processPayment with success: true. This server has no Wallet Orders web service, so Wallet can't show the order.

Button
Button label button.type

The words on Apple's button.

Button colour button.style
Button language button.locale

A language tag. Blank leaves it out.

Button size button.width button.height button.borderRadius button.padding button.boxSizing

CSS values. Blank leaves each out: the SDK uses width 100% and height 44px, and Apple's defaults are a 4px corner radius and no padding. The SDK raises a px size below Apple's minimum (30px high; 100px wide for plain, 140px with words) and logs a warning.

Divider text updateTextElement('walletDividerText')

Express Checkout only: the line between the Apple Pay button and the card form. Applied straight away, without a redraw. Blank sends nothing.

Merchant and cards
Merchant country countryCode

Apple: the country of your main place of business. Ask your payment provider which to use.

Currency currencyCode

The page also charges in this currency, on Spreedly's test gateway.

Card networks supportedNetworks

The sheet only offers cards on these networks. Apple's list is on its supported networks page. Some networks need a newer Apple Pay version.

Card types merchantCapabilities

Apple: supports3DS is required. supportsCredit or supportsDebit alone allows only that type. Add supportsEMV only if you take China Union Pay.

Card countries supportedCountries

The sheet only offers cards issued in these countries. Comma-separated ISO codes.

Contact details
Billing contact requiredBillingContactFields
Shipping contact requiredShippingContactFields

Tick postalAddress to get a shipping address, for delivery options and onShippingContactSelected.

Prefilled contacts billingContact shippingContact

A synthetic address on file, shown as the default in the sheet. The shopper can pick another. Apple needs postalAddress in the billing fields for a prefilled billing address, and at least one shipping field for a prefilled shipping contact. The SDK rejects the config otherwise.

Amounts in the sheet
Line items lineItems

Shown above the total. For a pending line the sheet shows "pending" instead of the amount, and the page leaves it out of the total.

Total type total.type
Payment type
Payment request recurringPaymentRequest automaticReloadPaymentRequest deferredPaymentRequest

Only one at a time. The SDK asks for Apple Pay version 14 for each. The billing amount is the subtotal, and managementURL is this site.

This server has no route for Apple's token notifications, so Apple's calls to the URL would fail.

Choices in the sheet
Delivery options shippingMethods

Standard (free) and Express (9.00). The page prices the order as if the sheet opens on Standard: Apple doesn't say which option it opens on, so device test M27 checks. dateComponentsRange adds delivery dates, and the SDK then asks for Apple Pay version 12.

Shipping type shippingType

How the sheet words delivery.

Coupon field supportsCouponCode couponCode

SAVE10 takes 10% off the subtotal. EXPIRED is expired. Anything else is invalid. The SDK asks for Apple Pay version 12.

Sheet callbacks

Each one returns the new total to the sheet. Untick one to see what Apple does without it.

Spreedly
Sandbox card testCardNumber

Spreedly stores this card number instead of the one in Apple's token, so the test gateway accepts it. Blank leaves it out.

Metadata metadata

Stored on the Spreedly payment method. key=value pairs, comma-separated. Blank leaves it out.

How this page works
  1. The page loads Apple's apple-pay-sdk.js and the Spreedly SDK.
  2. onValidateMerchant calls this server's /api/v1/apple-pay/validate.
  3. getAuthDetails calls /api/v1/auth/params for every attempt.
  4. The sheet callbacks work out the new total in this page.
  5. The SDK turns Apple's token into a Spreedly payment method.
  6. The page charges it with /api/v1/simple-purchase on the test gateway, for the total the sheet last showed.
