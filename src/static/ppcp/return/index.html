Why a separate page

With presentationMode: 'redirect' the buyer leaves the checkout page entirely, so the SDK instance is gone and onPaymentResult never fires for the success path. The outcome comes back on this URL instead. This matches how Spreedly's other offsite flows work — the SDK starts the redirect, the merchant owns the landing.

Flow

  1. Spreedly finalizes the authorization when the buyer returns through its own return URL
  2. It redirects here with ?transaction_token=
  3. This page POSTs to /ppcp/spreedly/transactions/:token/capture
  4. The server verifies the authorization succeeded, then captures

Local testing

Spreedly rejects localhost redirect URLs, so the buyer lands on the deployed Heroku origin. Swap the host for localhost:3000 by hand to capture against your local server.
