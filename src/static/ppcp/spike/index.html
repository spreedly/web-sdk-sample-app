Flow Steps
  1. Select products → cart total = amount
  2. Proceed → load PayPal v6 + local Spreedly SDK
  3. SpreedlyPPCP.mount() → createInstance + findEligibleMethods
  4. Render eligible buttons for the total
  5. Click → createOrder() → /ppcp/spreedly/orders (or /ppcp/orders for PayPal direct)
  6. Approve → capture → …/orders/:id/capture
SDK Configuration

Every option SpreedlyPPCP supports. Changing one re-mounts the buttons.

Presentation mode presentationMode

How PayPal shows the approval step.

Button text commit

Wording on PayPal's final button. Use Continue when your checkout has a review step after approval.

Redirect handling onRedirect

Supply the callback and the SDK hands you the URL instead of navigating — so you can save state first, or (on mobile) open it somewhere your app controls.

Only applies to redirect and mobile app-switch. Popup never navigates, so nothing fires.

PayPal's waiting overlay fullPageOverlay

The grey overlay PayPal draws over the page while the buyer is away approving. Turn it off if your own checkout already shows a waiting state.

Easiest to see in popup, which works on this page. It applies to redirect too.

Button colour buttonStyle.color

PayPal-family: gold, blue, white, black. Venmo: blue, black.

Corner radius buttonStyle

Any CSS length — 0, 4px, 9999px. Blank leaves PayPal's default (4px).

Button label buttonStyle.label

PayPal and Venmo only. Pay Later and Credit have no label control.

Test buyer country testBuyerCountry

Sandbox only. Overrides the country PayPal uses for eligibility — Venmo is US-gated.
